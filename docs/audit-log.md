# 操作审计模块

## 使用入口

管理员登录后，在功能导航点击“操作审计”，或访问 `/workspace/audit`。普通用户不能查询；后端再次检查数据库中的当前用户角色，不依赖前端隐藏按钮来保证权限。

页面提供用户名、操作类型、结果、请求编号和时间范围筛选，支持分页、刷新及展开详情。不提供修改、删除、清空或导出日志的接口。退出、登录失效和切换账号时清除审计查询缓存。

## 首次启用：先迁移，再发布

1. 确认目标环境和数据库名称，按环境流程完成备份与变更审批。脚本固定使用 `waht`；其他数据库名须先调整副本并审查。
2. 已初始化的数据库执行 `database/mysql/migration/20260918_001_add_audit_log.sql`。全新环境也要先运行基础初始化脚本，再执行此迁移。本次代码交付没有替你连接或修改 MySQL。
3. 核对 `waht_audit_log` 的字段、索引、字符集及应用账号权限，再发布后端和前端。`IF NOT EXISTS` 只避免重复创建，不会纠正一个已存在但结构错误的表。
4. 完成一次登录、笔记新增/编辑/删除，再用管理员查看记录，核对请求编号、操作结果与用户身份。
5. 回滚应用时保留新增审计表和已经产生的记录；不要为了回滚删除审计数据。历史操作不会自动补录。

建议应用账号在审计表上仅有 INSERT 和 SELECT 权限。当前模块自身没有 UPDATE/DELETE 操作，但不等于数据库具备防篡改能力；数据库管理员仍可能修改数据。

## 记录哪些操作

| 范围 | 操作类型 |
| --- | --- |
| 身份认证 | LOGIN 登录、REGISTER 注册 |
| 笔记写操作 | NOTE_CREATE 新增、NOTE_UPDATE 修改、NOTE_DELETE 删除、NOTE_PUBLISH 发布、NOTE_UNPUBLISH 撤回草稿 |
| AI 工作台 | CONVERSATION_CREATE 新会话、AGENT_MESSAGE 发消息、AGENT_APPROVAL 审批处理 |
| AI 内部回调 | AGENT_DRAFT_CREATE 创建笔记草稿 |
| 审计查询 | QUERY 查询审计记录 |

只审计带 `@Audited` 的接口。注解拦截器位于认证之前，所以已匹配这些接口的未认证请求也会记录。未匹配路由的 404、跨域预检、被更早的过滤器/网关拒绝的请求不在覆盖范围内。公开阅读、普通 GET 查询和浏览量更新不记录。

当前退出登录仅清理浏览器状态，没有服务端退出接口，因此不宣称能够记录退出登录。AI 的 Java 入口与实际创建草稿回调分别留痕，不记录 Python 内部每一步推理或工具读取过程。

## 字段及隐私边界

每条记录包含事件 UUID、请求开始时间、已验证用户 ID/用户名、模块、操作、对象 ID、HTTP 状态、业务码、接口处理结果、白名单业务状态、请求编号、HTTP 方法、路由模板、直接连接地址和处理耗时。

- 不采集请求/响应正文、完整请求 URL、查询参数、密码、Token、Cookie、笔记标题/正文、AI 提问/回复、异常堆栈或数据库错误文本。
- 成功登录/注册的身份来自业务返回的用户对象；其他请求身份来自现有认证或 Agent 委托认证。认证失败不记录调用方自称的用户名，页面显示“未认证”。
- 连接地址取原始请求的直接连接地址，忽略调用方伪造的转发头；经代理部署时通常是代理地址，不等于最终用户 IP。
- 对象 ID 用于关联业务对象，不保存修改前后全文快照；被删除笔记仍可通过对象 ID 追溯操作，但不能从审计日志恢复正文。
- 时间统一以 UTC 写入 DATETIME(6)，接口输出不带偏移的 UTC 时间，页面明确按 UTC 解析再转换为浏览器当地时间。时间筛选接口要求 ISO 8601 的带时区时间，如 `2026-09-18T10:00:00+08:00`；URL 中的 `+` 必须编码。
- 请求编号支持现有 `X-Request-Id` 规则，可由调用方提供且可能重复；事件 UUID 才是单条记录的唯一标识。需要关联 AI 入口和回调时，应核对各段实际传递的请求编号，不能仅凭重复编号认定同一笔操作。

## 结果语义与失败策略

`SUCCESS` 表示接口返回成功码，不等于所有远程步骤已最终完成。AI 审批还要结合业务状态：等待批准、拒绝批准或执行失败可能都以成功处理请求的接口响应返回。

`FAILURE` 表示鉴权拒绝、参数校验失败或明确业务拒绝。`UNKNOWN` 表示服务异常、上游不可用/超时、未能拿到统一响应码等，不能据此断言业务必然回滚或未执行。

审计在请求完成阶段写入，通过独立事务（`REQUIRES_NEW`，即另开事务提交）保留记录，不随业务事务回滚。写入失败不改变已经返回的业务响应，而是输出只含白名单字段的 `AUDIT_WRITE_FAILED` 错误日志，并累加 `waht.audit.write.failures` 指标。

这是一套“尽力记录”的应用审计，不是银行级无损审计：进程突然退出、业务成功后审计库不可用等情况可能导致数据库记录缺失。日志兜底需要部署方持久化采集并告警；目前没有自动重放兜底日志的任务。写入使用现有连接池，同步数据库故障仍可能占用请求线程或延长完成时间。

项目默认只暴露 health/info，新增计数器不意味着公网已能访问指标。需要监控采集时应在受控环境配置采集与访问保护，不要直接把诊断端点公开。

## 查询接口

`GET /api/admin/audit-logs`，返回现有 `BaseResponse<PageResponse<AuditEvent>>`。

- `page` 默认 1，范围 1–100000；`pageSize` 默认 20，范围 1–50，与既有分页插件限制一致。
- `username`（最长 50）、`action`（最长 40）、`outcome`、`requestId`（最长 64）为精确匹配；不传即不过滤，传空白字符串会拒绝。
- `from` / `to` 为可选时间范围，包含两个边界；按请求开始时间倒序、事件 ID 倒序稳定排序。
- 延续现有分页插件：超出总页数时回到第一页，响应提供实际页码；有并发新增记录时，页码分页仍可能发生跨页位移。
- 查询动作自身也记录一次，因此新查询记录通常在下一次刷新才看到，总数也会随刷新增长。

## 代码链路与扩展

`@Audited` 标记操作 → `AuditInterceptor.preHandle` 保存请求上下文 → 既有认证与业务逻辑 → `AuditResponseAdvice` 提取响应码和白名单身份/状态 → `afterCompletion` 汇总结果 → `AuditWriter` 独立事务 → `AuditMapper` → `waht_audit_log`。

新增写接口时显式添加 `@Audited(module = "...", action = "...", resource = "路径参数名")`，并更新前端操作名称。新返回类型若要记录对象 ID/业务状态，应在 `AuditResponseAdvice` 中逐字段白名单提取，禁止改成直接序列化整个请求或响应。

后端测试包括模拟请求的权限、脱敏、失败语义和代理地址验证，以及 H2 内存数据库中的真实 Mapper、分页、UTC 筛选和事务回滚验证。H2 测试不连接业务库，也不能代替目标 MySQL 环境的迁移验收。

日志保留期限、归档、清理、加密与防篡改存储需按部署环境另行确定；本次没有添加自动清理任务，避免擅自删除操作痕迹。
