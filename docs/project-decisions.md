# 项目决策记录

本文档记录 WAHT 的关键决策。后续如果方向变化，先改这里，再改代码。

## D001：后端先使用 Spring Boot 3

结论：当前阶段后端主线使用 Spring Boot 3。

原因：

- Java 是当前最熟悉的技术栈。
- Spring Boot 更适合先完成稳定业务。
- Go、AI、云原生都可以作为后续升级点。

影响：

- `backend/waht-java` 是第一阶段核心。
- `backend/waht-go` 暂时只保留 README。
- `backend/ai-service` 暂时只保留 README。

## D002：不强制参考 jinxi-platform

结论：WAHT 后端不再要求参考 `jinxi-platform`。

原因：

- WAHT 的定位、模块和成长路线不同。
- 当前要避免复制旧项目结构导致后续调整困难。
- 可以保留通用工程思想，但目录和模块按 WAHT 自身演进。

## D003：素材当前可以本地使用官方和网络素材

结论：当前阶段允许收集官方和网络素材，仅限本地学习使用。

限制：

- 不提交 GitHub。
- 不公开部署。
- 不商用。
- 不放入 `public-safe/`。

公开版本只使用：

- 自己原创素材。
- 已确认授权素材。
- 符合许可要求的开源素材。

## D004：当前不做 Docker 和 k8s

结论：当前阶段不生成 Docker 和 k8s 配置。

原因：

- 当前电脑 Docker 环境可能不稳定。
- 现阶段首要目标是 IDEA 能运行 Java 后端。
- 云原生是后续学习目标，不是第一阶段依赖。

## D005：按一天量推进

结论：每次生成或修改都控制在一天可理解、可消化的范围内。

原因：

- 项目是学习型长期项目。
- 一次生成过多会降低理解质量。
- 后续求职复盘需要能解释每一步为什么做。

## D006：前端使用 React + TypeScript + Vite

结论：当前用户前台和个人写作台使用 React、TypeScript、Vite、React Router 与 TanStack Query。

原因：

- Vite 本地启动和构建简单，适合当前学习阶段。
- TypeScript 可以固定前后端接口契约，项目禁止使用 `any`。
- 当前不需要 SSR，不提前引入 Next.js 的服务端部署复杂度。

## D007：公开内容与作者接口分离

结论：公开笔记使用 `/api/notes`，作者工作台使用受保护的 `/api/my/notes`。

原因：

- 草稿不能被公开接口读取。
- 写入操作必须验证 JWT、数据库用户状态和内容归属。
- 后续增加管理员或协作者时，可以在不破坏公开接口的情况下扩展权限。

## D008：本地配置只通过环境变量传递秘密

结论：数据库密码和 JWT 密钥不写入仓库，配置样例只描述变量名。

原因：

- 防止真实凭据进入 Git 历史。
- IDEA、命令行和构建产物可以复用同一套配置方式。
- Windows 系统变量修改后必须重启原有进程才能生效，运行文档需要明确说明。

## D009：笔记正文继续使用 Markdown 作为唯一数据源

结论：编辑器工具栏生成 Markdown，数据库只保存 Markdown 文本，不同时维护 HTML 或富文本 JSON。

原因：

- 公开详情和编辑预览可以复用同一渲染链路。
- 文本内容便于版本管理、迁移和后续 AI 检索。
- 避免多种正文格式之间出现同步错误。

## D010：本地草稿只做恢复，MySQL 是正式数据源

结论：浏览器在编辑后防抖备份草稿，恢复旧草稿必须由用户确认；手动保存成功后删除本地备份。

原因：

- 新建笔记在获得数据库 ID 前不适合频繁自动创建记录。
- 本地备份可以降低刷新、崩溃导致的内容丢失。
- 明确区分“本地恢复点”和“数据库已保存”，避免错误安全感。

## D011：主题视觉使用原创素材

结论：胡桃主题登录页使用项目生成的原创二次元场景，不使用游戏官方图片、Logo 或现成角色立绘。

原因：

- 保留暖红、梅花、灵蝶和可爱幽灵的情绪特征。
- 降低公开展示时的素材版权风险。
- 素材可随项目需求独立调整。
